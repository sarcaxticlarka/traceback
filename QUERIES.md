# Cypher and graph algorithms the product depends on

Generated by `python scripts/gen_queries.py` from the code that executes them (do not edit by hand). `$name` are query parameters; `{n}` marks an integer depth that is range-checked and interpolated (Cypher cannot parameterise variable-length bounds).

## Tools (agent-callable, also served over MCP)

### `recent_changes` — Q2 recent_changes

Deploys in the last N hours to the service or anything it depends on (up to `depth` hops), with the author and the dependency path that connects the deployed service to the alerting one. Prime suspects for root cause.

```cypher
MATCH (a:Person)-[au:AUTHORED]->(d:Deploy)-[dp:DEPLOYED_TO]->(x:Service)
WHERE x.id IN $ids AND d.ts >= $since AND d.ts <= $at
RETURN d.id AS did, d.sha AS sha, d.ts AS ts, d.status AS status, x.id AS xid, x.name AS svc, a.name AS author, a.id AS aid, ID(au) AS au, ID(dp) AS dp
ORDER BY ts DESC
LIMIT 400
```

### `hotspots` — Q15 hotspots (churn x fan-in)

Modules most likely to hurt when they change: ranked by lines changed in the last 90 days times (1 + direct dependents). Churn x fan-in is the classic risk signal.

```cypher
MATCH (s:Service)
WHERE s.churn_90d IS NOT NULL AND s.churn_90d > 0
RETURN s.id AS id, s.name AS name, s.churn_90d AS churn, s.dependents AS dep, s.commits AS commits, s.churn_90d * (1 + s.dependents) AS risk
ORDER BY risk DESC
LIMIT $top
```

### `bus_factor` — Q16 bus_factor

### `similar_incidents` — Q4 similar_incidents (vector + traversal)

Past incidents that are semantically similar to the signal on this service AND structurally close (affected service within 2 dependency hops, either direction). Hybrid vector + graph retrieval.

```cypher
CALL db.idx.vector.queryNodes('Incident','embedding',40,vecf32($v)) YIELD node, score
MATCH (node)-[af:AFFECTED]->(x:Service)
WHERE x.id IN $scope
MATCH (node)-[cb:CAUSED_BY]->(d:Deploy)
OPTIONAL MATCH (node)-[fw:FIXED_WITH]->(rb:Runbook)
RETURN node.id AS iid, node.title AS title, node.signal AS signal, score, x.name AS svc, ID(af) AS af, ID(cb) AS cb, d.sha AS sha, rb.title AS rb, ID(fw) AS fw, fw.result AS result
ORDER BY score
LIMIT 60
```

### `decision_lineage` — Q9 decision_lineage

Engineering decisions that constrain a service, newest first, with the decisions each one superseded and the source document it was recorded in.

### `ownership_gaps` — Q12 ownership_gaps

Services whose owning team has no current members (orphaned services), with who left and when.

```cypher
MATCH (t:Team)-[o:OWNS]->(s:Service)
WHERE o.vf <= $at AND o.vt > $at
OPTIONAL MATCH (p:Person)-[m:MEMBER_OF]->(t)
WHERE m.vf <= $at AND m.vt > $at
WITH t, s, o, count(p) AS active
WHERE active = 0
OPTIONAL MATCH (q:Person)-[m2:MEMBER_OF]->(t)
WHERE m2.vt <= $at
RETURN s.name AS svc, s.tier AS tier, t.name AS team, ID(o) AS oid, collect(q.name) AS left_names, collect(ID(m2)) AS left_edges, collect(m2.vt) AS left_ts
```

### `rank_runbooks` — Q5 rank_runbooks

Runbooks for an alert signal, ranked by learned success rate (procedural memory); runbooks recorded as fixing the specific service rank first.

```cypher
MATCH (rb:Runbook)-[fs:FOR_SIGNAL]->(sg:Signal {id:$sg})
OPTIONAL MATCH (i:Incident)-[:FIXED_WITH {result:'success'}]->(rb), (i)-[:AFFECTED]->(s:Service {id:$sid})
RETURN rb.id AS id, rb.title AS title, rb.attempts AS attempts, rb.successes AS successes, ID(fs) AS fs, count(DISTINCT i) AS local_wins
```

## Coordination (tasks and handoffs)

### `tbk/tasks.py::create_task`

```cypher
MATCH (i:Incident {id:$i})

```

```cypher
MATCH (t:Task {id:$t}), (b:Task {id:$b})

```

### `tbk/tasks.py::promote_ready`

```cypher
MATCH (t:Task {status:'blocked'})-[:FOR]->(:Incident {id:$i})
OPTIONAL MATCH (t)-[:BLOCKED_BY]->(b:Task)
WHERE b.status <> 'done'
WITH t, count(b) AS open_blockers
WHERE open_blockers = 0
SET t.status = 'ready'
RETURN count(t) AS n
```

### `tbk/tasks.py::claim_next`

```cypher
MATCH (t:Task {status:'ready'})-[:FOR]->(:Incident {id:$i})
WHERE t.kind IN $kinds
OPTIONAL MATCH (t)-[:BLOCKED_BY]->(b:Task)
WHERE b.status <> 'done'
WITH t, count(b) AS open_blockers
WHERE open_blockers = 0
RETURN t.id AS id, t.kind AS kind
ORDER BY t.priority DESC, t.created_ts
LIMIT 1
```

```cypher
MATCH (t:Task {id:$id, status:'ready'})
SET t.status = 'running', t.claimed_by = $a
RETURN t.id AS id, t.kind AS kind
```

### `tbk/tasks.py::upstream_findings`

### `tbk/tasks.py::list_tasks`

```cypher
MATCH (t:Task)-[:FOR]->(i:Incident)
WHERE $i = '' OR i.id = $i
OPTIONAL MATCH (t)-[:BLOCKED_BY]->(b:Task)
RETURN t.id AS id, t.kind AS kind, t.status AS status, t.priority AS priority, t.claimed_by AS claimed_by, i.id AS incident, t.created_ts AS created_ts, collect(b.id) AS blocked_by

```
